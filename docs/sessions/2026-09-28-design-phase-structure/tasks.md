## Verification results

**Task 1: render commands (2026-10-04).** Node and npx were at `/usr/local/bin`, and Google Chrome 148.0.7778.167 at `/usr/bin/google-chrome`. Every command ran in a temp directory outside the repo.

- **Mermaid (mermaid-cli 12.0.0):** `PUPPETEER_EXECUTABLE_PATH=/usr/bin/google-chrome npx -y @mermaid-js/mermaid-cli@12.0.0 -i {name}.mmd -o {tmp}/{name}.svg`. A `flowchart` with the four delta classDefs and an `erDiagram` both rendered. A syntax error exits 1, so the command works as a check. Without the env var (or `-p {puppeteer-config}.json` with `{"executablePath": "/usr/bin/google-chrome"}`), mermaid-cli looks for Puppeteer's `chrome-headless-shell`, which isn't installed here, and fails. An `erDiagram` with `classDef` and `A:::new` also parsed and rendered with the fill applied. GitHub rendering of that is unverified, so the delta list stays the source of truth there.
- **BPMN (bpmn-to-image 0.10.0):** `PUPPETEER_EXECUTABLE_PATH=/usr/bin/google-chrome npx -y bpmn-to-image@0.10.0 --no-footer {name}.bpmn:{name}.svg`. A minimal start → task → end diagram with DI rendered to SVG. Without the env var, the Chrome that Puppeteer downloads aborts with "No usable sandbox" (AppArmor user-namespace restriction). The system Chrome works with its sandbox on, so `--no-sandbox` is not needed.
- **Screenshot (headless Chrome):** `google-chrome --headless --disable-gpu --hide-scrollbars --window-size=1280,800 --screenshot={tmp}/ui-{screen}.png file://{tmp}/export/index.html`, run against an `index.html` in a temp directory. It wrote a 1280×800 PNG. The DBus/UPower errors on stderr are harmless.
- **Manual fallbacks (unchanged from the design):** "Export SVG" in bpmn.io or Camunda Modeler for BPMN; the Mermaid Live Editor for Mermaid; a hand-taken browser screenshot for the Claude Design export.

**Task 2: preload under the shared name `design` (2026-10-04, Claude Code 2.1.289).** The scratch plugin was outside the repo and renamed `compass-probe`, so it couldn't collide with an installed `compass-labs`. It held skill `design` (canary `AMBER-HERON-7731`) and agent `design` with `skills: [compass-probe:design]`. A control pair, skill `canary-control` (canary `COBALT-FINCH-4402`) and agent `control`, ruled out a general preload failure. Both agents had `tools: Glob` only, so they couldn't read file contents. Command: `claude -p "Use the Agent tool to start the subagent compass-probe:design ... then compass-probe:control ..." --plugin-dir {copy} --allowedTools=Agent < /dev/null`. Result: the `design` subagent reported `AMBER-HERON-7731` and the control reported `COBALT-FINCH-4402`. **Preload works with the shared name, so the skill keeps the name `design` (D12).**
