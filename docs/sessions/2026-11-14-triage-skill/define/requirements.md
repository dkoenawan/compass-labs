# Requirements: Triage skill

> Part of [index](index.md) · Define

## Requirements

REQ-028 to REQ-030 were added after REQ-027 was deferred, so they sit out of number order next to the rows they belong with.

EARS syntax. Each requirement has one acceptance criterion in Given/When/Then form. IDs are never reused; a dropped requirement is struck through, not deleted. A Won't meaning "never" is struck through with its reason; a Won't meaning "later" moves to the Deferred table below.

- **"Triage skill"** means the skill this session adds. Its final name follows the plugin rename (#34).
- **"Stock-take"** means one pass over every open issue that gives each a category, the evidence for it, its anchor mapping, its relations to other issues and a proposed action.
- **"Category"** means exactly one of: *covered by merged work*, *direction changed*, *duplicate or cluster*, *rewrite or narrow*, *still relevant*, *needs a user decision*.
- **"Report issue"** means the GitHub issue a run publishes, titled `Triage YYYY-MM-DD` (the date in the installed time zone) and labelled `triage`, holding the whole stock-take and its proposed actions grouped by category.
- **"Scheduled run"** means a run started by the installed schedule with no user present. **"Interactive run"** means a run the user starts and takes part in.
- **"Apply"** means an interactive run that carries out a stock-take's proposed actions, one group at a time, on the user's confirmation. A report issue is **unapplied** while it is open and no apply has run on it.
- **"Maintainer"** means the user who installs and runs the skill in a repository.
