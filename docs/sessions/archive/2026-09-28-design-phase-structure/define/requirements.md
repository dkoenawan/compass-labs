# Requirements: Design phase structure, with layered design skills and visual deltas

> Part of [index](index.md) · Define

## Requirements

EARS syntax. Each requirement has one acceptance criterion in Given/When/Then form. IDs are never reused; a dropped requirement is struck through, not deleted. A Won't meaning "never" is struck through with its reason; a Won't meaning "later" moves to the Deferred table below.

- **"Design phase"** means the Feature workflow's Design phase: its agent and the standard that agent follows.
- **"Design artifact"** means what the Design phase writes for a session. Today that is `design.md`; Design decides its shape.
- **"Solution kind"** means the category a solution belongs to: three-tier application, process/workflow, infrastructure, plugin/tooling, or other. Each solution has one **primary kind**.
- **"Scope checklist"** means the list of areas that might be in scope for a solution, whatever its primary kind, each marked in or out of scope with a reason. The areas are frontend, backend, database, infrastructure, process/workflow, visual UI design, and any other area the design names.
- **"In-depth path"** means the design guidance specific to a kind or a layer, beyond the sections every design has.
- **"Layer"** means, for a three-tier application, the frontend, the backend or the database.
- **"Stack area"** means a layer or the infrastructure.
- **"Significant choice"** means a design decision with more than one reasonable option whose outcome changes what gets built, such as extending an existing table versus adding a new one.
- **"Delta status"** means exactly one of *new*, *changed*, *deprecated* or *unchanged*, given to an element of the design by comparing it with the current state of the project.
- **"Established stack"** means the language, framework or tool a repository already uses for a stack area, as shown by its files (for example `package.json` dependencies, `pyproject.toml`, `prisma/schema.prisma`, `*.tf` or a CloudFormation template).
- **"Stack default"** means, per stack area:
  - frontend: React + TypeScript and its matching component ecosystem;
  - backend: Node.js with CQRS and Scalar API docs;
  - database: Postgres managed through Prisma;
  - infrastructure: Terraform.
- **"Visual UI design"** means how an interface looks: colour, typography, spacing, imagery and visual layout. It is distinct from components and their behaviour.
- **"Claude Design"** means claude.ai's design capability, to which visual UI design is delegated.
- **"Design gate"** means the orchestrator's approval step for the "Design complete" milestone.
- **"Project documentation"** means the project's Diátaxis docs that Close folds sessions back into: `docs/explanation/`, `docs/reference/` and `docs/registry/`, including its ADRs in `docs/registry/decisions/`.
- **"Past session folder"** means any folder under `docs/sessions/` other than the current session's, including everything under `docs/sessions/archive/`.
- **"Prior knowledge"** means earlier designs, established patterns, recorded decisions and descriptions of the current state that a design builds on.
- **"Software element"** means a `DES-*` item or significant choice that designs code: frontend or backend code in a three-tier application, or the skills, agents, hooks and scripts in a plugin/tooling solution.
- **"Principles check"** means a recorded judgement of a design element against **KISS** (keep it simple: no more parts or indirection than the requirements need) and **YAGNI** (you ain't gonna need it: nothing built for a need no live `REQ-*` states). For a software element it also covers **SOLID** (single responsibility, open/closed, Liskov substitution, interface segregation, dependency inversion). Each principle is marked *met*, or *traded off* with a reason, or (for a SOLID principle only) *not applicable* with a reason.

The acceptance criteria use one running example: **a member notification-preferences feature** in a repo whose `prisma/schema.prisma` has a `User` model, unless a row says otherwise.
