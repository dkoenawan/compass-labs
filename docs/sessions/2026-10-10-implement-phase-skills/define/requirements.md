# Requirements: Implement phase — an as-built artifact, the backend API artifact and the testing boundary

> Part of [index](index.md) · Define

## Requirements

EARS syntax. Each requirement has one acceptance criterion in Given/When/Then form. IDs are never reused; a dropped requirement is struck through, not deleted. A Won't meaning "never" is struck through with its reason; a Won't meaning "later" moves to the Deferred table below.

- **"As-built status"** means exactly one of *built as designed*, *deviated* or *not built*, recorded for a `DES-*` item at the end of Implement.
- **"Variation"** means any difference between what a frozen `DES-*` item (or the design's API contract) specifies and what Implement built, including a `DES-*` item not built.
- **"The design's API contract"** means the endpoints the frozen design specifies for the backend: method and path, request shape, response shape and error cases (`design/solution.md`'s contracts, refined by `design/backend.md` where it exists).
- **"Unit test"** means a test of one function, class or module in isolation. **"Component test"** means a test of one component, such as the backend service, through its own interface, with everything outside the component replaced by test doubles. **"Test-owned test"** means an integration, UI or Playwright test (one that exercises two or more real components together, or the user interface), or an inspection where the requirement is about a document or instructions. A harness test that runs real hooks and scripts together, such as this plugin's `tests/run.sh`, counts as an integration test (user decision, 2026-10-10).
- **"Backend `DES-*` item"** means a `DES-*` item whose Component cell names the backend layer.
- **"Layer home"** means `skills/{layer}/`, as fixed by ADR-004 D7.
