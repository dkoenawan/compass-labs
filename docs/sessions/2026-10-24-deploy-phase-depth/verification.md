How the checks were run, all at commit `1daffe6` on `feat/30-deploy-phase-depth`:

- **Agent runs.** The Deploy agent ran for real, with `claude -p --plugin-dir <repo> --agent compass-labs:deploy`, in a `cp -R` temp copy of each fixture, each `git init`ed on a `feat/1-change` branch with a session folder. The fixtures themselves are unchanged (`git status` clean under `tests/fixtures/`). The REQ-027 answers were relayed by resuming the same agent conversation (`--resume`), the way the orchestrator's `SendMessage` relays them.
- **Offer runs (REQ-026).** The `session` skill's one-time setup step 3 was driven with `claude -p`, with the user's answer given in the prompt, since `AskUserQuestion` can't be answered non-interactively.
- **Rehearsal of this session's own Deploy.** The agent ran in a local clone of this branch. Its `origin` was a local bare clone, and `gh` was a logging stub on `PATH` (`GH_TOKEN` set to an invalid value, so the real `gh` couldn't reach GitHub). The clone's `log.md` was edited to show a Test milestone, because the agent rightly refuses to deploy before Test is approved (its first rehearsal run returned `blocked` for that reason). Nothing was pushed to GitHub, and no tag or release was created.
- **Merge simulations.** The installed `.github/scripts/release-tag.sh` ran in clones whose `origin` was a local bare repo, with a stub `gh` whose `release create` pushes the tag to that bare origin, as GitHub does.
- **A limit of non-interactive runs.** Claude Code refuses a non-interactive write to `.claude/deploy.json` (it treats `.claude/` as a sensitive path), even with an explicit `Edit(<path>)` allow rule. So the paths that write the declaration (the REQ-027 yes, and REQ-026's "nothing to deploy" and "declare now") were stopped at the write. In each case the agent didn't try another route. Those writes are recorded `pending` below, with the interactive check to run.
